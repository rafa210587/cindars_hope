# Adopting external skills and tool adapters

Read only when selecting, importing or upgrading external instructions/integrations.

1. State the concrete missing operation or repeated failure. Map it to existing skills/agents
   before adding an entry. A useful reference does not need to become an installed skill.
2. Inspect primary source, revision, license, dependencies and actual implementation for risky
   operations. Preserve attribution/license if copying material. Record source date; pin the
   adopted revision rather than executing a moving remote installer.
3. Separate documented, installed, connected and locally verified states. A README claim is
   not compatibility evidence. Do not infer model abilities or savings from marketing metrics.
4. Check collision with project contracts: scope, Git, YAML, save IDs, event bus, import settings,
   UI/localization, validation and source catalog. Write project-specific guidance rather than
   stacking another mandatory planning/review framework over the harness.
5. For bridges, inspect executable/downloads, transport, bind/authentication, filesystem writes,
   generated config/skills, telemetry and runtime inclusion. Prefer an explicit local connection;
   model requests may still leave the machine. Do not describe local transport as offline inference.
6. Run a bounded candidate pilot only within authorized installation/execution scope. Compare
   output fidelity, recovery, changed files and actual effort against the current CLI/runner.
   Preserve rollback inputs and unrelated edits; do not use destructive Git cleanup.
7. Publish only the narrow accepted guidance through `.claude/` and regenerate copies. Retain
   unavailable integration checks as NOT RUN; optional adapters must not block working fallbacks.

Unity pilot: correct instance; scoped console/scene read; existing validator; relevant capture;
recompile/reconnect; isolated persistent edit; inspect uncertain mutation before retry;
preserve dirty scene. Aseprite pilot: use its
[adapter contract](../../aseprite-authoring/references/adapters.md).
