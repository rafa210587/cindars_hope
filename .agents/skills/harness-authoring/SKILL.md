# Skill: Harness authoring

The authoring source is .claude; the catalog is HARNESS_INDEX and Codex copies are generated.

**Core rule: keep the entry useful and load details only when the scenario needs them.**

## When to use
- Create or update a harness artifact, its triggers, references or operational boundaries.

## Essential checklist
- [ ] Scope/ownership and prior dirty changes identified.
- [ ] Specific trigger; core rule and output understandable from the entry.
- [ ] Conditional details have actual links and a reason to read them.
- [ ] Source catalog updated and copies generated by the responsible owner.
- [ ] Validation covers affected behavior as well as formatting.

## Procedure
1. Read the [authoring standard](../../../.claude/HARNESS_AUTHORING_STANDARD.md) and target artifact.
2. Define the decision the instruction should improve and its use scenarios; remove unsupported assumptions.
3. When a specific structure is needed, read only the relevant type in [formats](references/artifact-types.md).
4. Write a short entry with necessary boundaries. Separate substantial procedures by mode,
   without duplicating the reference in SKILL.md or requiring all references.
5. Register ID/trigger in the [source catalog](../../../.claude/HARNESS_INDEX.md); preserve router discovery.
6. Check links and scenarios with [harness-audit](../harness-audit/SKILL.md); generate copies after sources freeze.

## Validation
When selecting or upgrading external skills/MCP, read [external capability adoption](references/external-capabilities.md)
for provenance, compatibility and a bounded pilot; do not load it for ordinary local edits.

To create an entry, adapt the [skill template](assets/templates/skill-entry.md).
If unsure which details to separate, consult the [disclosure example](references/examples/conditional-art-review.md).
These resources are optional for a small correction, not mandatory reading steps.

Small text changes need link/routing review. Script changes need relevant success and
failure tests. Use independent review when risk/complexity justifies it, with no agent quota.
Do not infer token or cost savings from bytes, size or configured effort alone.

## When NOT to use
- Author a spec, ADR or gameplay document: use its document workflow.
- Audit without edit authorization: `harness-audit`, returning findings.

## When to stop and report
Explicitly report a missing reference, contract conflict or change outside ownership;
continue independent work already authorized. Do not request approval again for an in-scope correction.

## Expected output
Changed source files and references, catalog/generation, performed checks and remaining limits.
