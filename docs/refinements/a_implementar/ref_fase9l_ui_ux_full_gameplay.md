## Decisões preservadas

FASE9L deve separar o DebugHud de uma HUD real de gameplay. O escopo conhecido inclui Inventory UI, Equipment UI, Hotbar final, Skill tree UI, Crafting UI, Cave entry/loadout UI, HUD de exploração, HUD de combate, HUD de cave run, morte/retorno/corpo recuperável, Fonte de Anya, feedback de ação, tooltips, item comparison, drag/drop ou seleção por slot, estados vazios, estados bloqueados, estados de erro, controle teclado/mouse, save/load feedback, Shop UI, Bestiary UI futura, Character sheet, Attribute allocation UI, Respec UI e Active skill slots UI.

## Itens que devem virar implementação

- [ ] Spec completa de UI/UX antes de código.
- [ ] Wireframes ou fluxo textual validado.
- [ ] Separação entre HUD debug e HUD final.
- [ ] Priorização por tela e jornada de gameplay.

## Fora de escopo / cuidado

- Não tratar este arquivo como aprovação para implementar UI final.
- Não substituir DebugHud sem migração planejada.
- Não misturar UI final com sistemas futuros ainda sem contrato.
